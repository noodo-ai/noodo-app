# Noodo app

Read [docs/engineering.md](docs/engineering.md) before changing or reviewing app code. It is the source of truth for repository engineering conventions. Read [README.md](README.md) for current behavior and development setup.

For requested code reviews, use the shared `noodo-review` skill when available. It owns scope selection, independent review passes, evidence, and reporting; repository rules remain in the engineering document. If unavailable, review against these sources directly, include requirements and runtime correctness, and report the scope and verification limits.

Use `noodo-ui-standards` when available for frontend structure, visual language, interaction, accessibility, and visual verification. Repository rules and explicit user requirements take precedence over general skill guidance. Missing optional skills do not block work.

Keep project rules in the engineering document and reusable workflow guidance in skills. Update the relevant document when an intentional architecture or contract change makes it stale.
